# FILTER.md — 텍스트 판정 기준

- **상태**: DRAFT. 팀이 정한 기준을 옮겨 적었고, 아직 정해지지 않은 곳은 `(미정)`으로 표시했다. 추측으로 채우지 않는다
- **적용 범위**: **텍스트 doodle의 글자**(D-07: 최대 50자). 그림 doodle은 §5
- **관련**: D-19(검사 제공자), D-35(ML 검사 범위), D-42(PROPOSED, 판정 합성), `docs/specs/07-moderation-frame.md`. 코드 주석이 이 문서의 §2, §3을 가리킨다
- **이 문서의 역할**: "무엇을 막고 무엇을 통과시키는가"의 기준만 둔다. 어떻게 구현하는지는 07 명세에서 정한다

## 1. 카테고리와 처리

| 카테고리 | 이름 | 처리 |
|---|---|---|
| 1. 욕설, 비하 | `PROFANITY` (코드의 기본 카테고리 이름. 확정 필요) | 필터링을 거쳐 **글자 크기를 10으로 줄여서 게시** |
| 2. 혐오·차별 | `HATE` | **거부** (전면 금지) |
| 3. 성적인 내용 | `SEXUAL` | **거부** (전면 금지) |
| 4. 개인정보 | `PERSONAL_INFO` | **거부** (전면 금지) |

> 결정: 2, 3, 4는 전면 금지. 1번은 필터링을 거쳐 최대 10pt.

- "10pt"는 글자 크기 10을 뜻한다. 허용 글자 크기 목록(`graffiti.doodle.font-sizes`)의 **최솟값이 이미 10**이라, "최대 10pt"는 "10으로 고정"과 같다
- 줄이는 목적은 욕설이 캔버스의 점유율을 차지하지 않게 하는 것이다. 점유율은 텍스트 박스가 덮는 칸에서 계산되므로(D-14) 글자가 작아지면 점유율도 같이 줄어든다

### 카테고리 1. 욕설, 비하

(미정) 아직 본문이 없다. 채워야 할 것:
- 정의: 무엇이 욕설이고 무엇이 비하인가
- 줄이는 예시, 그대로 통과하는 예시
- 2번 `HATE`와의 경계: 특정 집단을 겨냥하면 `HATE`(거부), 그 밖의 욕설은 1번(축소)으로 가르는 것이 맞는지
- 카테고리 이름 확정

### 카테고리 2. 혐오·차별 (`HATE`)

**막음**: 특정 성별, 지역, 국적, 장애, 외모를 비하하거나 "~는 다 ~하다"고 몰아가는 문장.

- "여자들은 다 김치녀", "한남충 꺼져", "전라도 사람은 믿으면 안 됨", "조선족 다 나가라", "애자같이 그리네", "틀딱들 왜 옴"

**통과**: 차별을 비판하거나 설명하는 문장.

- "장애인 비하 표현 쓰지 맙시다", "지역 차별 그만", "모두 환영해요 🌈"

### 카테고리 3. 성적인 내용 (`SEXUAL`)

**막음**: 노골적인 성적 표현이나 신체 묘사, 성적인 제안.

**통과**: 연애나 사랑을 이야기하는 일반 문장.

- "OO야 사랑해", "솔로 탈출 기원", "커플 축하해요"

(미정) 막는 예시가 아직 없다.

### 카테고리 4. 개인정보 (`PERSONAL_INFO`)

**막음**: 누구든 특정할 수 있는 연락처나 식별 정보. **본인 정보여도 막는다**(공개 캔버스라서).

- "010-1234-5678로 연락해", "abc@khu.ac.kr", "2023123456 김OO", "OO동 OO아파트 101동"

**통과**: 사람을 특정하지 못하는 말.

- "경영 23 화이팅", "중도 3층 최고", "공대생 파이팅"
- "인스타 @hong_123 팔로우": `@`로 시작하는 SNS 아이디는 막지 않는다

> 결정(2026-10-29, 현):
> - 숫자 사이의 공백, 하이픈, 점은 **지우고 비교**한다. "010 1234 5678", "010.1234.5678"도 전화번호로 본다
> - 한글로 쓴 숫자("공일공 일이삼사…")는 형식 검사로 잡지 않고 **ChatKHU에 맡긴다**
> - 주소는 형식 검사로 잡지 않고 **ChatKHU에 맡긴다**
> - `@`로 시작하는 SNS 아이디는 **막지 않는다**
>
> 개인정보는 금칙어 목록이 아니라 형식(정규식) 검사로 막는다. 검사의 위치와 형식 목록은 07 명세에서 정한다

## 2. 정규화 규칙 (미정)

단어 비교 전에 글자를 정리하는 규칙이다. 현재 코드(`TextNormalizer`)는 기본 정규화만 한다: NFKC, 소문자, 글자와 숫자만 남김(공백, 문장부호, 기호, 제로폭 문자 제거). 아직 기준이 없는 것:
- 닮은꼴 글자 바꾸기
- 자모 분해
- 한영 전환

개인정보(카테고리 4)의 형식 검사(전화번호, 이메일, 학번)는 숫자 사이의 공백, 하이픈, 점을 지운 글자에서 한다(§1 카테고리 4 결정). 이메일은 `@`와 `.`가 있어야 하므로 원문에서 찾는다.

## 3. 금칙어와 예외 목록

- 파일: `backend/src/main/resources/moderation/banned-words.txt`, `allowed-words.txt`. 1차 목록이 들어 있다(2026-10-29, 현 검토). 욕설, 혐오, 성적인 단어만 있고 개인정보는 없다
- 형식: 한 줄에 `단어 [카테고리]`. 카테고리를 생략하면 `PROFANITY`
- 예외 목록은 금칙어를 포함하지만 일반 말인 단어를 위한 것이다. 예: "시발점"
- 공백을 지운 뒤 부분 문자열로 찾으므로, 띄어 쓴 두 단어가 붙어서 걸릴 수 있다. 예: "어머니 미역국"은 "니미"에 걸린다. 이런 사례가 나오면 예외 목록에 넣는다
- 문맥이 없으면 일반 말과 구별할 수 없는 단어(꺼져, 보지, 자지, 홍어, 조선족, 씹)는 목록에서 뺐다. ChatKHU 단계 몫이다
- 현재 코드는 **어떤 카테고리의 단어든 거부**한다. 1번(`PROFANITY`)을 줄이기로 했으므로 카테고리별로 처리가 달라져야 한다 (07 명세)
- 목록을 고칠 때는 이 문서와 같은 PR에서, `WordListTest`에 막는 예와 통과 예를 하나씩 추가한다

## 4. 판정 흐름 (확정된 것만)

텍스트는 금칙어 → ChatKHU → OpenAI 순으로 검사한다(D-19).

- 어느 단계에서든 카테고리 2, 3, 4가 걸리면 거부
- 카테고리 1이 걸리면 거부하지 않고 크기를 줄여서 게시
- **D-19의 "하나라도 걸리면 거부"는 카테고리 1에는 더 이상 맞지 않는다.** 새 결정 D-43(PROPOSED)으로 올렸다. 팀이 확인하면 ACCEPTED로 바꾼다
- **(미정) 거부와 축소가 겹칠 때**: 예를 들어 욕설과 개인정보가 함께 있는 글. 07 명세는 추천안 "거부 > 보류 > 축소"로 썼다(`specs/07-moderation.md` §5.3). 확정 필요

## 5. 그림 doodle과의 경계

이 문서는 텍스트만 다룬다. 그림 doodle은 시각 내용을 OpenAI 이미지 검사와 자체 ML이, 손글씨는 OCR로 글자를 뽑아 이 문서의 기준으로 판정한다(D-35).

> 결정(2026-10-28): **크기 축소는 텍스트 doodle에만 적용한다.** 그림 doodle에서 욕설(카테고리 1)이 나오면 줄이지 않고 관리자 검토(`HELD`)로 보낸다.

이유: 그림을 줄이려면 획 좌표를 축소하고 굵기를 허용 목록(2, 4, 8, 16)에 맞춰야 해서 복잡하고, 손글씨 OCR은 정확도가 낮을 수 있다(D-35). 카테고리 2, 3, 4가 그림에서 나오면 기존대로 거부된다.

## 6. 07 명세에서 정할 것 (기준이 아니라 구현)

추천안은 `specs/07-moderation.md`에 썼다(§5, §11 결정 목록).


- 줄인 뒤 bbox와 청크, 점유율을 다시 계산하는 방법. 텍스트 bbox는 클라이언트가 재서 보내는 값이다(D-31, PROPOSED). 추천은 비례 축소(폭과 높이에 `10 / 원래 크기`를 곱함)이고, 서버가 글꼴을 직접 재지 않는다
- 원래 글자 크기를 어디에 남기는가(관리자가 되돌릴 때 필요), `moderation_state`에 새 값이 필요한지(DB 마이그레이션)
- 작성자에게 줄어서 게시됐다고 알리는 한국어 안내 문구. 쿨다운은 이미 소모된 상태다(INV-08)
- OpenAI omni-moderation의 카테고리(harassment, hate, sexual, violence 등)를 위 4개에 어떻게 대응시킬지, 목록에 없는 카테고리(폭력 등)는 어떻게 할지
- ChatKHU의 응답 `{"flagged","category","reason"}`의 `category`와 위 4개의 대응
- 판정 합성의 우선순위(`VerdictCombiner`, D-42)

## 7. 예시는 테스트가 된다

위 막음, 통과 예시는 구현 때 테스트 케이스로 그대로 쓴다. 예시를 고치면 같은 PR에서 테스트도 고친다. "통과" 예시(예: "장애인 비하 표현 쓰지 맙시다")는 단어 목록만으로는 통과시킬 수 없어서 ChatKHU 단계가 가리는 몫이다.
