## 4. 점유율과 페이지 순환

### D-14 점유율 계산 — ACCEPTED
- **그림**: 획을 **선분 단위 bbox**(이웃한 두 점마다, 선 굵기만큼 여유 포함)로 덮이는 칸
- **텍스트**: 텍스트 박스 bbox가 덮는 칸
- 칸마다 **참조 카운트**를 유지(추가 +1, 삭제 -1). 카운트 > 0인 칸 비율 = 점유율
- **이유**: 원의 안쪽 빈 공간은 세지 않는다는 팀 규칙을 지키면서, 구현은 bbox 수준으로 단순하게

### D-15 페이지 넘김 조건 — ACCEPTED (D-15a 대체)
- 상태는 `ACTIVE → COUNTDOWN → ENDED` **한 방향** (INV-03)
- 점유율 **70%** 도달 시 **6시간** 카운트다운 시작. 점유율이 다시 내려가도 **취소하지 않음**
- 페이지 최대 수명 **7일**. 종료 시각 = `min(생성 + 7일, 70% 도달 + 6시간)`
- 7일이 지나면 **낙서가 없어도** 넘김
- ~~D-15a: 50% 도달 시 카운트다운~~ — SUPERSEDED by D-15

### D-16 넘김 안내와 초안 처리 — ACCEPTED
- 상단에 점유율과 페이지 시작 날짜(`YY/MM/DD부터`) 상시 표시. 남은 시간(`N시간 N분 남음`)은 카운트다운이 켜진 뒤에만 표시 (2026-10-24 현 수정, 09 §9)
- **T−5분부터** 화면 상단 왼쪽에 큰 카운트다운 + 경고 문구 "페이지가 넘어가면 그리고 있는 초안도 사라져요"
- 넘어가면 **초안은 폐기**하고 새 페이지로 자동 전환. 옛 `pageId`로 들어온 요청은 `PAGE_ENDED`로 거절(자동 재전송 없음)

### D-17 아카이브 열람은 MVP 제외 — ACCEPTED
- 지난 페이지 목록과 열람 화면, API는 만들지 않음
- **데이터는 지우지 않고** DB에 보관(`status=ENDED`). 나중에 아카이브 기능을 붙일 수 있게

### D-19 검사 제공자 — ACCEPTED
- **텍스트**: ① 금칙어 1차 필터 → ② **ChatKHU**(JSON 응답 `{"flagged","category","reason"}`) → ③ **OpenAI omni-moderation** 이중 검사. 하나라도 걸리면 거부 (욕설은 D-43으로 바뀜)
  - ChatKHU 응답 파싱 실패 → 그 단계만 통과로 보고 로그 기록 (D-42: `UNCHECKED`로 게시)
  - 검사 기준(종류별 예시, 금칙어 목록, 정규화)은 `docs/FILTER.md`
- **그림**: 서버에서 Java2D로 PNG 렌더링 → **OpenAI omni-moderation**(이미지). ChatKHU는 이미지 입력 미지원
- 모든 제공자는 `ModerationProvider` 인터페이스 뒤에 둠
- **한계 인지**: 손글씨 한국어 욕설은 놓칠 수 있음 → 관리자 삭제로 보완
- **추가**: 그림에는 자체 ML 모델(이미지 분류 + OCR)이 더해짐 → D-34 ~ D-39

### D-34 자체 ML 모더레이션 모델 = 추가 검사층 + 그림자 모드 시작 — ACCEPTED
- **결정**: 자체 학습 모델(선정성, 폭력성, 부적절성 판별)을 기존 검사(D-19)에 **하나 더 추가**하는 `ModerationProvider`로 붙인다. 어느 검사든 걸리면 거부
- **출시 직후에는 그림자 모드**: 모델이 판정은 하지만 결과는 기록만 하고 거부에 쓰지 않음. OpenAI 판정, 관리자 판정과 비교해 정확도 기준을 넘으면 실제 차단에 사용
- **이유**: 처음 학습한 모델의 실제 정확도는 운영 데이터로만 확인 가능. 서비스 위험 없이 평가 숫자를 얻고, 관리자 조치 기록을 정답 라벨로 재활용
- **역할**: OpenAI가 약한 영역(손글씨 한국어 욕설, 학교 맥락의 부적절한 내용) 보완
- 세부(입력 범위, 서빙 위치, 학습 데이터, 그림자 모드 종료 기준)는 후속 결정에서 확정

### D-35 자체 ML 검사 범위 — ACCEPTED
- **그림 doodle의 시각적 내용**(선정, 폭력, 혐오 이미지): 자체 **이미지 분류 모델**. 입력은 `DoodleRenderer`가 만든 PNG
- **그림 doodle 안의 손글씨**: ML 서버의 **OCR**로 글자를 추출 → 기존 텍스트 검사(금칙어, ChatKHU, OpenAI)에 넘김
- **타이핑한 텍스트 doodle**: 자체 모델 없이 기존 3중 검사(D-19) 유지
- **이유**: 텍스트는 문자열이 이미 있어 기존 검사가 효율적. 손글씨는 그림 doodle이라 문자열이 없으므로 OCR이 필요. 무료(D-04)이고 팀 ML 파트 범위
- **한계와 대안**: 마우스로 쓴 한글 손글씨의 OCR 정확도는 낮을 수 있음 → 그림자 모드(D-34)에서 측정 후, 부족하면 비전 LLM 제공자로 교체(유료)
- **텍스트 검사 난이도 참고**: 타이핑 텍스트 < 그림의 시각적 내용 < 손글씨 순으로 어려움. 부적절한 낙서에 라벨을 붙인 공개 데이터셋은 사실상 없어서 운영 데이터가 핵심

### D-36 ML 서버는 같은 EC2의 컨테이너로 — ACCEPTED
- **결정**: Python ML 서버(이미지 분류 + OCR)를 같은 EC2의 Docker Compose 컨테이너로 추가하고, 인스턴스를 메모리 4GB급으로 상향. GPU 없이 CPU 추론
- **격리**: 내부 네트워크에서만 접근(외부 포트 없음), 컨테이너 메모리 상한(`mem_limit`)으로 Spring과 MySQL 보호
- **호출 방식**: OpenAI 검사와 **병렬** 호출, ML 전용 제한 시간(예: 3초). 그림자 모드에서는 시간 초과나 장애를 "판정 없음"으로 기록만 하고 게시에는 영향 없음
- **이유**: 게시량이 적어(30분 쿨다운) CPU로 충분. 서버 1대 유지로 관리 단순. 서버리스는 콜드 스타트가 5초 제한을 넘기기 쉬움
- **재검토 시점**: 그림자 모드를 끝내고 실제 차단에 쓸 때, 부하를 보고 전용 서버 분리 여부 결정
- D-04(EC2 소형 1대)의 인스턴스 크기를 이 결정으로 조정

### D-37 첫 이미지 모델은 제로샷 → 운영 데이터로 미세조정 — ACCEPTED
- **출시 시점**: CLIP 같은 이미지-텍스트 사전학습 모델의 **제로샷 분류**. 카테고리는 문장으로 정의(예: 성기를 그린 낙서, 혐오 상징). 카테고리 이름은 `FILTER.md`의 이름(`SEXUAL`, `HATE` 등)을 쓰고, 폭력 그림은 자체 모델이 보지 않는다(OpenAI 이미지 검사와 관리자 삭제에 맡김, 2026-10-28). 학습 데이터 없이 동작
- **이후**: 그림자 모드에서 쌓인 실제 낙서와 관리자 판정을 라벨로 **미세조정**
- **평가 기준 세트** (2026-10-28 수정): 모델을 바꿀 때마다 같은 세트로 비교
  - 정상 낙서: 공개 데이터셋 Google Quick, Draw!(CC BY 4.0, 출처 표기)의 획 좌표를 우리 캔버스 크기와 선 굵기로 다시 렌더링해서 수천 개
  - 부적절한 낙서: 팀이 직접 그린 것(카테고리마다 30~50개)과, 모양이 정해진 혐오 상징을 코드로 변형(회전, 크기, 선 떨림)해 만든 것
  - 부적절 표본이 적어 재현율 오차가 크므로, 이 세트의 수치는 임계값의 출발점으로만 쓴다. ENFORCE 판단(D-39)은 그림자 모드 운영 데이터로 한다
  - 이전 기준("팀이 앱에서 직접 그린 부적절한 낙서와 정상 낙서 각 수백 개")은 모으기 어려워 바꿈
- **이유**: 출시 시점에 학습 데이터가 0이고, 사진 기반 NSFW 모델은 선 그림에서 정확도가 낮을 가능성이 높음

### D-38 학습 데이터 사용은 필수 동의에 포함 — ACCEPTED
- **결정**: 첫 로그인 필수 동의의 이용 목적에 "부적절한 낙서 판별 모델 개선"을 포함. 별도 선택 동의는 두지 않음

### D-39 그림자 모드 종료 기준 — ACCEPTED

### D-42 애매하거나 AI가 실패하면 일단 게시하고 관리자가 사후 확인 — PROPOSED (D-18 장애 처리를 애매 판정까지 넓힘)
- **결정**: ChatKHU가 `REVIEW`(애매)를 주거나, 어느 AI 검사든 시간 초과·오류·형식이 틀린 응답이면 doodle을 **게시**하고 `UNCHECKED`로 표시한다. 관리자 화면의 미검사 목록에서 보고 부적절하면 삭제한다(D-23 ①). ChatKHU 판정은 `PASS` / `BLOCK` / `REVIEW` + 카테고리 + 이유 한 줄(이유는 저장하지 않음)
- **이유**: 보류(`HELD`)는 캔버스에 나오지 않아서, 관리자가 볼 때까지 사용자 낙서가 사라진 것처럼 보인다(2026-10-29 현 결정: "일단 게시하고 관리자가 검사했을 때 부적절하면 삭제"). 확실한 위반(거부)은 그대로 막는다
- **영향**: `HELD`는 스텁만 지난 낙서(키가 없어 실제 검사를 못 함, `graffiti.moderation.unchecked=HOLD`)에만 남는다. 관리자의 게시 낙서 삭제(10)가 공개 전에 있어야 한다
- **알려진 위험**: AI가 오래 멈추면 검사 안 된 낙서가 캔버스에 쌓인다. 쿨다운 30분이 사용자당 상한이고, 금칙어·개인정보 형식 검사는 외부 API 없이 항상 돈다
- **명세**: `specs/07-moderation-frame.md`(틀), `specs/07-moderation.md`(실제 검사)

### D-43 욕설은 거부하지 않고 텍스트는 10pt로 줄여 게시 — PROPOSED (D-19 "하나라도 걸리면 거부"를 카테고리 2~4로 좁힘)
- **결정**: 검사에서 욕설·비하(`PROFANITY`)만 나오면 텍스트는 글자 크기를 10으로 줄이고 bbox를 비례 축소해서 `PASSED`로 게시한다. 그림(손글씨 포함)은 줄이지 않고 `UNCHECKED`로 게시(관리자 사후 확인, D-42). 혐오(`HATE`), 성적(`SEXUAL`), 개인정보(`PERSONAL_INFO`)는 그대로 거부. 겹치면 거부가 우선이고, 애매·실패와 겹치면 `UNCHECKED` + 축소
- **이유**: FILTER.md §1 결정(2, 3, 4는 전면 금지, 1은 최대 10pt). 작게 하면 점유율도 줄어든다(D-14). 그림 축소는 획 좌표와 굵기를 다시 맞춰야 해서 복잡하다(FILTER.md §5)
- **영향**: 욕설이 나와도 다음 검사를 계속 돌린다(뒤 검사가 개인정보나 혐오를 찾을 수 있게). 원래 크기는 `moderation_detail`에 남긴다
- **명세**: `specs/07-moderation.md`

### D-44 텍스트 글꼴은 웹 배포가 허용된 것만 자체 호스팅 — ACCEPTED (현, 2026-10-29)

- **이유**: 웹폰트는 방문자 브라우저로 파일을 내려보내므로 재배포에 해당한다. 한글 TTF는 2~9MB라 그대로 쓸 수 없다
- **명세**: `specs/13-text-fonts.md`

### D-45 텍스트 너비 상한을 글자 크기의 125%로 — ACCEPTED (현, 2026-10-29, D-31의 너비 상한을 바꿈)
- **결정**: 텍스트 bbox 너비 상한은 `글자 크기 × 가장 긴 줄의 글자 수 × text-width-percent(125)%`를 올림한 값. 높이 상한(1.4배)은 그대로
- **이유**: 잘난체(W 1.05em), 카페24 써라운드(% 1.08em)처럼 1em보다 넓은 글자가 있는 글꼴이 있다. 올림은 D-43 축소 후에도 상한을 넘지 않게 하려는 것
- **명세**: `specs/13-text-fonts.md`
